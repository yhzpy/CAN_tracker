## 引言
本设计文档围绕GB/T 27930电动汽车充电通信协议的状态机进行系统化说明，结合仓库中已有的解析与记录实现，给出从初始连接到正常充电再到断开连接的完整生命周期。同时补充J1939多包传输（CM/DT/ACK）的实现要点，包括连接管理、数据传输、确认机制与组包重组算法。

需要特别说明的是：当前代码库实现了协议报文解析与数据记录，但未直接实现“协议状态机”的显式状态转换逻辑。因此，本文在“架构总览”和“详细组件分析”中，基于现有解析入口与报文类型，提出一套可落地的状态机设计方案，并在“附录”中严格映射到实际的多包传输实现。

## 项目结构
本项目为STM32F4 + FreeRTOS平台，主要涉及：
- 应用层任务：CAN报文接收、GB/T 27930解析、SD卡日志记录、LCD显示
- 协议解析模块：按CAN ID分发到各报文解析函数，并输出结构化结果
- J1939多包传输：在默认分支中处理CM/DT/ACK三类报文，完成组包与重组

### GB/T 27930 状态机设计（建议方案）
虽然当前代码未实现显式状态机，但基于已支持的报文类型，推荐如下状态与转换规则：

- 初始化状态：系统启动和设备检测
  - 触发：上电、CAN初始化完成
  - 行为：等待CHM/BHM握手报文；若超时则进入异常处理
- 握手阶段：CHM/BHM报文交换和参数协商
  - 触发：收到CHM或BHM
  - 行为：解析协议版本、最高允许电压等参数；校验兼容性
- 辨识阶段：CRM报文和设备身份确认
  - 触发：收到CRM
  - 行为：解析辨识结果与充电机编号；失败则重试或中止
- 准备阶段：BRO/CRO状态检查和能力匹配
  - 触发：收到BRO/CRO
  - 行为：检查双方“准备就绪”标志；匹配CML能力范围
- 充电阶段：BCL/CCS实时数据交换
  - 触发：BRO/CRO均就绪后开始
  - 行为：周期解析BCL(需求)/CCS(输出)，监控异常
- 统计阶段：BSD/CSD数据收集和记录
  - 触发：充电结束或定时采集
  - 行为：汇总SOC变化、能量输出、时间等
- 中止阶段：BST/CST异常处理和清理
  - 触发：BST/CST或错误报文(BEM/CEM)
  - 行为：记录原因码，清理资源，回到初始化或待机

### J1939多包传输状态机（实际实现）
当前实现位于Parse_1939，包含：
- CM：连接管理，开启传输（携带总字节数、包个数、PGN）
- DT：数据传送，按包序号写入缓冲区，维护接收标记数组
- ACK：确认接收与接收完成
- 重组完成后根据PGN类型进一步解析BRM/BCP/BCS

```mermaid
flowchart TD
Start(["进入Parse_1939"]) --> CheckType{"CAN ID类型"}
CheckType --> |CM| CM["解析CM<br/>设置bytecnt/packcnt/pgn"]
CheckType --> |DT| DT["解析DT<br/>写入rxbuf[offset]"]
CheckType --> |ACK| ACK["解析ACK<br/>更新packnum/完成标志"]
CM --> Next["继续接收"]
DT --> Complete{"所有包是否到达?"}
Complete --> |是| Reassemble["重组完成<br/>按PGN解析BRM/BCP/BCS"]
Complete --> |否| Next
ACK --> Next
Reassemble --> End(["返回ParseResult_t"])
Next --> End
```

## 性能与实时性考虑
- 解析路径轻量：每个解析函数仅做字段提取与格式化，避免复杂计算

## 故障排查指南
- 相同报文去重：RecordTask会判断extId、len与data是否完全一致，避免重复记录

## 附录：J1939多包传输实现要点
- 连接管理(CM)
  - 解析总字节数、包个数、PGN
  - 初始化接收缓冲与状态
- 数据传输(DT)
  - 校验包序号有效性
  - 计算偏移与拷贝长度，写入rxbuf
  - 维护packReceived数组标记已接收包
- 确认机制(ACK)
  - 区分“确认接收”与“接收完成”
- 组包重组算法
  - 当所有包到达后，按PGN类型进一步解析BRM/BCP/BCS
  - 完成后清空接收标记数组

```mermaid
sequenceDiagram
participant Sender as "发送端"
participant Receiver as "接收端(Parse_1939)"
Sender->>Receiver : CM(开启传输)
Receiver-->>Sender : ACK(确认接收)
loop 数据包
Sender->>Receiver : DT(第N包)
Receiver->>Receiver : 写入rxbuf[offset]
Receiver-->>Sender : ACK(确认接收)
end
Sender->>Receiver : DT(最后一包)
Receiver->>Receiver : 重组完成
Receiver-->>Sender : ACK(接收完成)
```
