### 会话 1：解决项目乱码问题（2026-10-05，9 轮）

**讨论的问题**

1. 为什么用 Qoder/VSCode 打开项目，中文注释全是乱码？
2. GBK 和 UTF-8 编码的区别是什么？为什么 Keil 下正常、编辑器下乱码？
3. 怎么批量检测项目里每个 .c/.h 文件的编码？
4. 怎么把 GBK 文件批量转成 UTF-8？要不要加 BOM？
5. `delay.c` 为什么转换后还是乱码？（发现是历史上被错误保存损坏，备份也损坏）
6. 转码后 Keil（ARM Compiler 5）编译、烧录会不会受影响？
7. 转码后串口打印中文会不会乱？终端软件要怎么设置？
8. 编辑器明明转好了为什么还显示乱码？（IDE 编码检测缓存问题）

**核心结论**

- 项目混合编码：正点原子标准文件为 GBK（24 个），用户改过的文件为无 BOM UTF-8（14 个）；
- 处理方案：24 个 GBK → UTF-8 with BOM；14 个补 BOM；原件备份到 `Project/_gbk_backup/`；
- `delay.c` 历史损坏无法恢复，改用纯 ASCII 英文注释重写（代码逻辑不变）；
- Keil AC5 正确处理 UTF-8 BOM，编译烧录不受影响；
- **运行时行为变化**：固件里的中文字符串从 GBK 变成 UTF-8 字节序列，串口终端（如 XCOM）必须设为 UTF-8 才能正常显示中文；
- IDE 会缓存旧的编码检测结果，必要时重开标签页或用纯 ASCII 绕过。

### 会话 2：SD卡配置步骤及文件完整性（2026-10-08，13 轮）

**讨论的问题**

1. SD 卡初始化的完整步骤（11 步）是什么？
2. 上电后为什么要发至少 74 个时钟周期？代码里为什么是"循环发 74 次 CMD0"？
3. CMD0（GO_IDLE_STATE）把卡置于什么状态？Idle 状态的定义？
4. Idle 状态下卡能接受哪些命令？（CMD1 / ACMD41 / CMD58 电压协商）
5. CMD8 是干什么的？怎么鉴别 SD 2.0+ 卡？
6. CMD55 + ACMD41 轮询 OCR 的流程？busy 位（bit31）什么含义？
7. 什么时候算初始化完成（Ready 状态）？RCA 什么时候分配？
8. SDSC / SDHC / SDXC 卡类型怎么识别、有什么区别？
9. 初始化失败（超时）怎么排查？

**核心结论**

- 每次 CMD0 帧占 48 个时钟周期，74 次是协议规定的上限兜底（确保卡完成上电复位 POR）；正常情况首次即成功退出循环；
- CMD0 → **Idle 状态**（未分配 RCA，仅接受电压协商命令）；
- CMD8 鉴别卡代际（SD 2.0+）→ CMD55+ACMD41（SD 卡）或 CMD1（MMC）轮询 OCR busy 位，busy=1 表示进入 **Ready 状态**，完成电源就绪与类型识别；
- 初始化时序链：上电 74 clk → CMD0 → CMD8 → ACMD41/CMD1 → CMD2(CID) → CMD3(RCA) → CMD9(CSD) → CMD7(选中) → ACMD6(4bit 总线) → 配置时钟 → 完成。

### 会话 4：sdio主要寄存器（2026-10-09，13 轮）

**讨论的问题**

1. SDIO 外设有哪些主要寄存器？（POWER / CLKCR / ARG / CMD / DCTRL / DTIMER / DLEN / STA / ICR / MASK / DCOUNT / RESP1-4 / FIFO）
2. CPSM 和 DPSM 是什么？为什么要两个独立状态机？
3. 为什么 `sdmmc_read_blocks` 里要先使能 DPSM 再使能 CPSM？
4. DMA 的 `PeripheralDataSize` / `MemoryDataSize` 为什么都配成 Word（32 位）？和 SDIO FIFO 宽度什么关系？
5. FIFO 模式是什么？内部缓冲几级？
6. Burst 模式是什么？INCR4/8/16 什么意思？
7. 为什么 FIFO + Burst 都开启时要求 PSIZE == MSIZE？
8. STM32F103 的 DMA 和 F407 有什么区别？F103 代码能直接用 F4 的 FIFO/Burst 配置吗？
9. SPL 库迁移到 HAL：`DMA_Cmd` / `DMA_ITConfig` / `DMA_Init` 对应 HAL 什么函数？
10. `DMA_FlowControllerConfig` 在 HAL 里有对应吗？
11. HAL 的 DMA 中断还要不要手动清标志位？回调机制怎么工作？
12. 为什么 SDIO 命令宏定义写成 `((uint8_t)0U)` 而不是 `0`？
13. FreeRTOS 二值信号量在 ISR→任务同步中怎么用？和 Linux 的 completion 有什么区别？

**核心结论**

- **双状态机**：CPSM 管 CMD 线（命令路径），DPSM 管 DAT 线（数据路径），可独立启停；**必须先 `SDIO_DPSM_Enable` 再 `SDIO_CPSM_Enable`**，保证卡应答后数据通路立即就绪；
- **F1 vs F4 DMA**：F103 无 FIFO、无 Burst、无 Stream/Channel 层级；F2/F4 有 4 级 × 32bit FIFO、支持 Burst（INCR4/8/16）、FIFO+Burst 时强制 PSIZE==MSIZE；`DMA_FIFOMode_Enable` 等 API 在 F103 上不存在；
- **SPL→HAL 映射**：`DMA_Init + DMA_ITConfig + DMA_Cmd` → 合并为 `HAL_DMA_Start_IT()`；`DMA_FlowControllerConfig` → HAL 无对应（仅双缓冲模式有效，勿映射）；中断处理从手动 `DMA_GetITStatus/ClearITPendingBit` → `HAL_DMA_IRQHandler` 自动分发到 `HAL_DMA_XferCpltCallback` / `HAL_DMA_XferErrorCallback`；
- **宏定义规范**：`U` 后缀使字面量为 unsigned（避免符号转换警告），`(uint8_t)` 强转匹配寄存器字段宽度（CMDINDEX[5:0]），是 ST 库的典型风格；
- **信号量**：`xSemaphoreCreateBinary` 用于 ISR→任务同步（ISR give、任务 take）；FreeRTOS 支持带超时阻塞和 ISR 安全 give，Linux 中断上下文不能用信号量、要用 completion。

### 会话 8：过滤器配置讲解（2026-10-10，4 轮）

**讨论的问题**

1. CAN 过滤器怎么配置？掩码模式和列表模式区别？
2. 本项目过滤器为什么配成 32 位全 0（不过滤）？
3. CAN 波特率 250kbps 怎么算出来的？`can1_init(1,6,7,12)` 四个参数什么意思？
4. 采样点 57% 合理吗？传统 CAN 一般多少？

**核心结论**

- 过滤器：掩码模式、32 位全 0 = 全通过、接入 FIFO0（`can.c:84-93`）；
- 位时序：SJW=1、BS1=6、BS2=7、BRP=12（寄存器写入时减 1）；APB1=42MHz，tq=12/42MHz≈285.7ns，每位 1+7+6=14 tq，波特率 = 42MHz/(14×12) = **250kbps**（GB/T 27930 要求）；
- 采样点 = (1+BS1)/14 = 8/14 ≈ **57%**，属于"早采样"（传统 CAN 常用 75%~87.5%），短距离低速总线可接受，高噪声环境可能欠佳；
- CAN1_RX0 中断优先级 = 5，处于 FreeRTOS 安全区。

### 会话 9：SD卡写入链路（2026-10-10，1 轮）

**讨论的问题**

1. 从 `f_write` 到 SDIO 硬件的完整写入调用链？
2. `sd_write_disk` 里的地址转换逻辑对不对？（发现 Bug）
3. SDSC 卡和 SDHC 卡的寻址方式区别？
4. 驱动层的双层同步机制怎么分工？
5. DMA 写单块/多块的命令序列（CMD16/CMD24/CMD25）？
6. 写完怎么知道成功？中断和信号量怎么配合？

**核心结论**

- **分层架构**：上层外壳 `sd_read_disk`/`sd_write_disk`（FatFs 适配层：互斥保护 + 地址换算 + 委托下层）→ 下层内核 `sdmmc_read_blocks`/`sdmmc_write_blocks`（static 私有：配 DMA/DPSM、发 CMD 序列、阻塞等 `g_sdio_transfer_sem`）；
- **发现 Bug**：`sd_write_disk` 用 `CardType != STD_CAPACITY_SD_CARD_V1_1` 判断是否左移 9 位——SDSC v1.1 卡（≤2GB）被漏掉，扇区号直接当字节地址用，**寻址偏差 512 倍**；正确写法应为 `CardType != HIGH_CAPACITY_SD_CARD`；且代码注释把"高容量卡用字节地址"写反了（事实：SDSC 字节寻址、SDHC 块寻址）；
- **双层同步**：应用层 `xSDCardMutex` 保护 f_open→f_write→f_close 整段；驱动层 `g_sdio_mutex` 保护单次块传输；`g_sdio_transfer_sem`（二值信号量）由 SDIO/DMA 中断 give，实现软硬同步；
- 中断优先级 SDIO=6、DMA2_Stream3=5，均 ≥ 5，FromISR API 安全。

### 会话 10：f_mount用法（2026-10-10，8 轮）

**讨论的问题**

1. `f_mount` 三个参数什么意思？第三个参数 opt=0 和 opt=1 区别？
2. FATFS 结构体是干什么的？为什么要用户自己分配（项目里用 mymalloc）？
3. f_mount 到底做了什么？"注册"和"挂载"是一回事吗？
4. 延迟挂载（opt=0）时，真正的挂载发生在什么时候？
5. `mount_volume` 内部流程？disk_initialize 调用链走到哪？
6. 引导扇区什么时候读？读到哪？BPB 怎么解析？
7. 项目里 SD_Card_Init 任务怎么用的 f_mount？

**核心结论**

- `f_mount(fs, "0:", opt)`：先把 fs 对象**注册**进全局表 `FatFs[vol]`；opt=0 延迟挂载（不读盘直接返回），opt=1 立即调 `mount_volume` 强制挂载；
- 项目用法：`f_mount(fs_obj, "0:", 1)`（app.c:451）立即挂载；FATFS 对象是"空台账"，f_mount 负责"注册 + 从 SD 卡抄数据填满它"；
- `mount_volume` 是**幂等挂载器**：`fs_type != 0` 已挂载 → 只查 disk_status 直接返回；未挂载 → `disk_initialize`（→ diskio.c → sdio_sdcard.c 的 sd_init，硬件初始化让卡能读）→ `find_volume`（内部 check_fs 把引导扇区读进 `fs->win[512]`，定位 FAT 卷）→ 解析 BPB 填充 FATFS 对象（csize/fatbase/database 等）；
- 所有文件 API（f_open/f_read/f_write）入口都调 `mount_volume` 兜底，保证"用文件前卷一定挂载好"。

### 会话 11：确认队列即FIFO（2026-10-10，5 轮）

**讨论的问题**

1. FreeRTOS 的队列（Queue）是不是就是 FIFO？
2. 队列和信号量、互斥量的本质区别？
3. 硬件 FIFO（SDIO FIFO、UART FIFO）和软件队列有什么异同？
4. 队列满了怎么办？本项目哪里会丢数据？

**核心结论**

- FreeRTOS 队列本质是**带阻塞能力的环形 FIFO 缓冲区**（数据按值拷贝进出），先进先出；
- 信号量/互斥量底层也是队列（计数为 0/1 或 0~max 的特殊队列），区别在用途：队列传数据、信号量做同步、互斥量做资源保护（带优先级继承）；
- 硬件 FIFO 是外设内的物理缓冲（如 SDIO 4 级×32bit、USART 无 FIFO 靠 DMA），软件队列是 RAM 里的 RTOS 对象；
- 项目丢数据点：can1_rx_queue 深度 10，满则 ISR 里丢包计数（can.c:186-224）。

### 会话 12：计算阻塞时间（2026-10-10 22:49 ~ 10-11，9 轮，当前会话）

**讨论的问题（完整记录）**

1. `xQueueReceive` 第三个参数是不是阻塞时间？`wait_time` 怎么算的？（app.c:335-339）
2. `accumulate_buffer + buffer_pos` 为什么数组能做加法？（app.c:350）
3. 指针居然可以和整数做加法？为什么 C 允许？
4. 指针减指针为什么合法？
5. 三种信号量的 take 函数都是 `xSemaphoreTake` 吗？（app.c:50）
6. `mount_volume` 在 f_mount 里用过，为什么 f_open 里也用？它是不是初始化 SD 卡、读引导扇区？（ff.c:3819）
7. f_open 里 mount_volume 之后那一大段（ff.c:3824-3995）在做什么？
8. `fp->obj.fs = fs` 这个绑定是建立起关联吗？

**核心结论**

- **动态阻塞时间**：`elapsed = xTaskGetTickCount() - last_receive_time`；已超 60s → wait_time=0（不阻塞，立即走超时分支刷盘）；未超 → 阻塞剩余时间 `pdMS_TO_TICKS(60000) - elapsed`。tick=1000Hz，1 tick=1ms。目的：超时点精确锚定在"最后一次收数据 + 60s"，即使循环内有耗时操作也不漂移；无符号 tick 相减天然抗回绕；
- **数组名退化为指针**：`accumulate_buffer + buffer_pos` ≡ `&accumulate_buffer[buffer_pos]`，标准指针算术；char 元素 1 字节，偏移量正好等于已累积字节数，实现追加；
- **指针 + 整数**是 C 刻意设计：`a[i] ≡ *(a+i)`，下标运算符就是指针加法的语法糖；编译器自动按 `n × sizeof(元素)` 缩放；
- **指针 − 指针**得到元素个数差（`ptrdiff_t`），是"指针+整数"的逆运算，`(p+n)-p==n`；前提是同一数组内，跨数组相减是 UB；指针+指针无物理意义所以被禁止；
- **信号量 API 统一**：二值/计数/互斥三种 take/give 都用 `xSemaphoreTake`/`xSemaphoreGive`（句柄统一为 `SemaphoreHandle_t`，底层都是队列，区别仅在创建函数和内核行为）；**唯一例外**：递归互斥锁必须用 `xSemaphoreTakeRecursive`/`xSemaphoreGiveRecursive`；互斥锁 give 必须由持有者执行；ISR 里只能 give（FromISR）不能 take；
- **mount_volume 幂等挂载**：f_mount 负责登记（opt=1 时立即调它），f_open 等所有文件 API 负责兜底；已挂载走短路分支只查 disk_status；
- **f_open 主体流程**（ff.c:3824-3995）：`follow_path` 解析路径找目录项 → 合法性检查（NS_NONAME / chk_share）→ 创建模式分支（dir_register 注册新目录项 / FA_CREATE_ALWAYS 截断清簇链）或打开已存在文件分支（目录/只读检查）→ 初始化 FIL（sclust/objsize/fptr/flag，追加模式沿 FAT 簇链跳到文件尾并预读尾扇区到 fp->buf）→ FREE_NAMEBUFF → LEAVE_FF 解锁卷；
- **`fp->obj.fs = fs`**：指针赋值建立"文件对象 → 卷对象"的从属引用（非拷贝）；之后 f_read/f_write 全靠它访问卷级共享资源（`fs->win[]` 共享扇区缓冲、csize/fatbase/database、pdrv）；配套 `fp->obj.id = fs->id` 记录挂载代际号，卷被重挂载后旧文件对象会被识别为失效（FR_INVALID_OBJECT）。
